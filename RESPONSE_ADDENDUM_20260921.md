# Reviewer Response Addendum (2026-09-21)

> We thank the reviewer for asking us to separate algorithmic effects from baseline configuration and run-to-run variability. We expanded the supplementary record rather than reporting only the most favorable configuration.
>
> We fixed the local batch size, local training period, client count, concurrency, buffer size, model, development seed, development budget, selection metric, formal round budget, and evaluation seeds. For FedBuff and DirBridge, the applicable development grid is `local_lr in {0.003, 0.01, 0.03, 0.05}` and `global_lr in {0.1, 0.5, 1.0}`. The development seed is kept separate from the five formal seeds. We report final, tail-10, tail-50, per-seed values, standard deviations, and paired confidence intervals where the complete formal matrix is available.
>
> The revised results show that FedBuff and DirBridge can be very close after a stable server step is selected. On CIFAR-10 alpha=0.1 with the matched `local_lr=0.03, global_lr=0.5` setting, the tail-10 means are 66.758 +/- 3.205 for FedBuff and 66.000 +/- 3.933 for DirBridge. On the high-skew profile, the corresponding values are 67.459 +/- 2.745 and 67.524 +/- 2.129. On CIFAR-100 alpha=0.5 with `local_lr=0.05, global_lr=0.5`, FedBuff is higher than DirBridge by 1.541 tail-10 points. We therefore no longer claim universal accuracy superiority for DirBridge.
>
> We also report the failure modes rather than using them as headline evidence. FedBuff is sensitive to the effective asynchronous server step because an overly large step amplifies stale-update variance, while an overly small step slows progress. CA2FL and FADAS require method-specific diagnosis because their exposed parameters and adaptive update rules differ. The E1 record documents the CA2FL server-step sensitivity and FADAS effective-step/moment diagnostics. We explicitly distinguish completed audits from unfinished formal runs.
>
> Finally, we audited and repaired the online initialization path. The current implementation separates in-flight client results from server-visible observations, delays feature/group updates until arrival, consumes each arrival exactly once, and assigns a newly observed client to an existing centroid when a periodic reclustering pass is not due. The event-level and metric-persistence regression tests pass in the reference environment. The repaired five-seed online/full-warm CIFAR-100 comparison is reported separately in `e2-online-init/postfix_audit/RESULTS_CURRENT.md`; both arms contain historical non-finite test-loss records, so we do not claim fully healthy finite training. The repaired oracle-versus-estimated comparison remains pending because the new ten-run record contains only A/D, not B/C.
>
> Our revised claim is conditional: DirBridge is designed to correct direction-level representation deficits caused by latency-dependent arrivals. The mechanism need not improve final accuracy when the realized direction-latency coupling is weak or when a tuned FedBuff remains stable. We report both the settings where the methods are close and the settings where the coupled profile produces a clearer separation.
